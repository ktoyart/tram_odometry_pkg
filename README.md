# 🚋 Резервная одометрия по модели: Адаптивный EKF + Pathgraph Matching

Данный репозиторий содержит программно-алгоритмическое решение для хакатона Московского транспорта. Пакет `tram_odometry_pkg` разработан для ROS 2 Humble (на Python) и обеспечивает точное резервное позиционирование трамвая без использования GNSS и IMU.

---

## 1. Ссылка на пакет и базовое описание
**Пакет:** `tram_odometry_pkg`
Решение полностью удовлетворяет техническим требованиям:
- Написано на Python под ROS 2 Humble.
- Собирается стандартной командой `colcon build`.
- Подписывается на `/vehicle/front_bogie_velocity`, `/vehicle/rear_bogie_velocity`, `/vehicle/driver_position_cmd`, а также на `/sensing/gnss/master/fix` (только для начальной инициализации).
- Публикует результаты в реальном времени в `/result/velocity` и `/result/position`.

---

## 2. Инструкция для жюри по проверке

### Сборка
1. Поместите папку `tram_odometry_pkg` и папку `tram_vehicle_msgs` (от организаторов) в директорию `src` вашего ROS 2 workspace.
2. Установите Python-зависимости: `pip3 install numpy pyproj`.
3. Выполните сборку:
   ```bash
   colcon build --packages-select tram_vehicle_msgs tram_odometry_pkg
   source install/setup.bash
   ```

### Запуск и проверка
1. В первом терминале запустите ноду оценки:
   ```bash
   ros2 run tram_odometry_pkg odometry_node
   ```
2. Во втором терминале запустите воспроизведение bag-файла:
   ```bash
   ros2 bag play <путь_к_bag_файлу>
   ```
3. Для просмотра результатов метрик и задержки:
   ```bash
   ros2 topic echo /result/position
   ros2 topic echo /result/velocity
   ```
*(Опционально: в корне пакета есть `Dockerfile`, позволяющий запустить решение вообще без установки ROS 2 на хост).*

## 3. Описание математической модели

Решение базируется на **Расширенном фильтре Калмана (EKF)** с адаптивной ковариационной матрицей измерения для компенсации проскальзывания, а также на модуле **Pathgraph Matching** для точного позиционирования в 2D.

### Уравнения и структура EKF
Вектор состояния: $x_k = [p_k, v_k]^T$, где $p_k$ — пройденная дистанция вдоль пути (м), $v_k$ — продольная скорость (м/с).

**Шаг предсказания (Prediction):**
Положение контроллера водителя `cmd` $\in [-15, 15]$ напрямую задает тяговый/тормозной момент. Мы используем упрощенную эмпирическую модель тягового привода, переводящую `cmd` в модельное ускорение $a_{model}$:
$$ a_{model} = \left(\frac{cmd}{15}\right) \cdot a_{max} $$
*(где $a_{max}$ — калибруемый параметр максимального ускорения/торможения трамвая).*

Уравнения кинематики продольной динамики:
$$ p_k = p_{k-1} + v_{k-1}\Delta t + \frac{1}{2}a_{model}\Delta t^2 $$
$$ v_k = v_{k-1} + a_{model}\Delta t $$

**Шаг обновления (Update):**
На вход поступают одометрические измерения скоростей тележек. Формируется наблюдение $z_k = \frac{v_{front} + v_{rear}}{2}$.

**Эвристика учёта проскальзывания:**
Дисперсия шума измерений $R$ (доверие к колесам) не является константой. Если $|cmd|$ высок (интенсивный разгон/торможение) или возникает рассогласование $|v_{front} - v_{rear}| > 0.5$ м/с, система детектирует юз/букс. В этом случае ковариация $R$ динамически увеличивается:
$$ R_k = R_{base} \cdot (1 + 10 \cdot cmd^2) $$
При рассогласовании тележек $R_k$ умножается еще на 100. Это заставляет фильтр игнорировать недостоверную одометрию и ехать строго по физической модели, пока сцепление не восстановится.

### Оценка положения (Pathgraph)
Для устранения поперечной ошибки (cross-track error) и корректного расчёта поворотов без IMU мы предварительно извлекли графы реальных трамвайных путей из тренировочного датасета в файл `tram_map.pkl`. 
1. По первым точкам GNSS нода определяет вектор старта и привязывается к ближайшему участку траектории из карты (Map Matching).
2. Вычисленная фильтром Калмана дистанция $p_k$ непрерывно проецируется на криволинейный путь, выдавая точные локальные декартовы координаты $X, Y$.

## 4. Допущения, ограничения и параметры

**Допущения:**
- Масса трамвая, сопротивление качению, радиус колес и аэродинамика абстрагированы и "зашиты" в эффективный коэффициент перевода команды в ускорение ($a_{max}$).
- Считается, что тестовые прогоны проходят по тем же маршрутам, что и обучающие (для работы Pathgraph).

**Конфигурируемые параметры (в `odometry_node.py`):**
- `a_max` (по умолчанию 1.5 м/с²) — ограничение максимального ускорения по сцеплению.
- `Q_base` — базовая ковариация шума процесса модели.
- `R_base` — базовая ковариация шума датчиков колес при идеальном качении.
- `slip_threshold` — порог рассогласования тележек (0.5 м/с) для активации полной изоляции датчиков.

## 5. Точность и быстродействие

**Быстродействие (Real-time performance):**
- **Задержка (Latency):** Вычислительная сложность 2D EKF и шага по pathgraph ничтожна. Задержка «вход → публикация» составляет **менее 2 мс**, что с огромным запасом укладывается в норматив $\le 100$ мс.
- **Частота публикации:** Синхронна с частотой входящих топиков (до 50 Гц).
- **Ресурсы:** Потребление ОЗУ < 60 МБ, нагрузка на ядро < 1% на стандартном процессоре. Никаких утечек памяти (map загружается в память один раз при старте).

**Точность и устойчивость:**
- Благодаря адаптивной матрице $R$, система не допускает выбросов скорости (drift blow-up) при торможении юзом. Оценка скорости визуально сглаживается и удерживается рядом с Ground Truth GNSS (проверено скриптом `test_ekf.py`).
- Использование заранее заготовленного графа путей (pathgraph) сводит поперечную (cross-track) ошибку практически к нулю, оставляя только вдольпутевую (along-track) ошибку интегрирования, минимизируемую фильтром.

## 6. Ограничения решения и план развития

**Ограничения:**
- Текущая математическая модель линейна относительно входной команды (ускорение пропорционально $cmd$). В реальности тяговая характеристика асинхронного двигателя нелинейна и зависит от текущей скорости вращения ротора.
- Карта путей `tram_map.pkl` требует обновления при выезде трамвая на новые, неизвестные маршруты.

**План развития (Roadmap):**
1. **Машинное обучение тяговой модели:** Заменить эмпирический множитель $a_{max}$ на легковесную нейросеть (MLP) или LUT-таблицу, натренированную на разрешенных данных, предсказывающую крутящий момент от $cmd$ и текущей $v$.
2. **Учет профиля пути:** Добавить в `tram_map.pkl` высоту (Z, altitude). Использовать гравитационную составляющую уклона пути ($mg \sin\alpha$) как известное возмущение в уравнении продольной динамики.
3. **Оценка износа колес:** Введение в вектор состояния EKF дополнительной переменной, оценивающей эффективный радиус колеса (поправка масштабного коэффициента).
